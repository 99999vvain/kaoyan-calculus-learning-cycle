# 已知限制与未决事项

本文件是项目**对外承诺的边界**。README 的"已知限制"一节指向这里；这里的每一条都应当能在代码或记录里找到依据。

只写**当前仍然成立**的问题，不写改动历史。

标注：**P1** 影响数据安全或核心正确性；**P2** 影响可用性与一致性；**P3** 体验或整洁度。

---

## 一、数据安全

### P1 · 学习数据存放于技能目录内部

`data/` 位于 skill 目录里。以整目录覆盖方式升级或替换 skill 时，学习记录可能被清掉。

- **现有保护**：`data/backup/` 按日快照；`scripts/backup_data.py --dest <路径>` 可做异地备份；`SKILL.md` 要求在更新前提示先备份。
- **未解决**：没有把数据目录搬到技能目录之外的机制。宿主若能配置外部数据路径，应改为可配置。
- **披露方式**：README 与本文均明确标注。**不要宣称此风险已彻底解决。**

### P1 · 更新与恢复目前全靠手动流程

没有任何自动迁移、版本兼容或崩溃恢复机制。更新流程见 README「备份、恢复与更新」，全部步骤都是人工执行。

- 恢复方式：把 `data/backup/<日期>/` 下四个文件复制回 `data/`。
- 如果脚本不可用：四个文件都是纯 Markdown，可直接用任意编辑器打开、复制、另存，不依赖脚本。
- `backup_data.py` 用退出码区分结果：`0` 完整、`1` 找不到数据目录、`2` 全部缺失、`3` 部分缺失（快照不完整）、`4` 目标目录不可用。**非 `0` 一律视为备份未成功**，不要据此更新 skill。完整的场景表见 `TESTING.md` 第 6 节。

## 二、判定规则

### P1 · 时间数据缺失会导致状态卡住

升级到 `已掌握` 的硬条件是「零提示 **且** 限时内完成」。但计时只能靠学习者口头报告。

- 实测：本项目 8 行应试记录中，5 行用时为 `未记录`。
- 后果：知识点会长期停在 `待复习`，看起来像系统坏了，实际是数据不足。
- **未解决**：没有"没计时也能给出有界判断"的降级设计。
- **禁止的错误做法**：用"计划时长"顶替"实际用时"来绕过限制。那是伪造数据。

### P1 · 长周期规则未在真实使用中触发

以下规则已设计，但真实使用中一次都没跑过，属于未验证路径：

| 规则 | 位置 | 触发次数 |
|---|---|---|
| `需回炉` + 1/3 天双复测（R5、R6） | `teaching-rules.md` §3 | 0 |
| 章末复习（20 分钟流程） | `coaching-rules.md` §8 | 0 |
| 周复盘模板 | `coaching-rules.md` §5 | 0 |
| R1 / R2 / R4 / R7 / R9 | `teaching-rules.md` §3 | 未单独验证 |
| 距上次学习 > 14 天的恢复流程 | `SKILL.md` §10.3 | 0 |

对外描述必须写"已设计，未实测"，不能写"已验证"。

### P2 · 应试能力维度只覆盖一种题型

已有 8 行记录全部为「解答」题型，`选择` / `填空` 从未记录。而考研数学一选择题占比不低。

- **未解决**：缺少选择/填空的题量与限时口径（例如选择题单题限时、填空题必须给最终值）。

### P2 · `未记录` 与"不追问"的张力

`coaching-rules.md` 规定连续 3 次 `未记录` 才问一次，但升级判定又依赖时间数据。实际使用中出现过"连续追问用时让学习者反感"的情况。

- **未解决**：缺少一条明确的"何时可以问、问几次、被拒绝后怎么办"的收敛规则。

### P3 · 知识点台账的 `next_review` 缺少终止条件

`data-format-spec.md` 只规定 `next_review` 可以写日期或 `-`，且 `-` 表示"不再排期"，但**没有定义知识点什么时候可以置 `-`**。错题档案有明确规则（连续两次复测通过 → `已归档`，`next_review` 记 `-`），知识点台账没有对应的终止条款。

- 后果：要么无限期复习下去（`next_review` 永远有值），要么由使用者自行判断何时置 `-`，两人做法可能不同，且事后无法区分"该终止"与"漏填"。
- 本轮未修：补这条规则等于新增判定条件，超出"修正可靠性缺陷"的范围。已记录，待维护者定。

### P3 · 知识地图由 AI 生成，未逐条校核大纲原文

`knowledge-map.md` 的八章骨架对应考试大纲的板块划分，但**知识点粒度、`K-章.节.序` 编号、前置依赖与「数一要求」等级均由 AI 生成**，**且未逐条对照大纲原文校核**，也不是从某份讲义的目录结构搬来的。考纲微调时不会有任何提示。

- 影响：若某年考纲增删考点，地图不会自动反映，推导出的目标深度 `T` 可能失真；AI 归纳的依赖关系也可能本身有误。
- 现有缓解：`knowledge-map.md` 第 4 层允许按讲义增补；台账中已实际学过并验证的点（`已掌握` / `已学待验`）算局部验证，但覆盖面有限，不构成整体校核。
- 使用建议：以你手上的官方大纲与讲义为准；发现不符时改本文件，不要反过来信地图。**不要把本文件当作权威考点清单引用。**

### P3 · 个别知识点的「数一要求」标注可能偏低

**深度规则本身已不再冲突**：`assessment-rubric.md` 第 2.1 节把"目标深度 T"与"记录深度 D"分开——T 只决定还练不练，不封顶台账的 D 值。因此即使某点标为「理解」（T=D2），学习者凭证据达到 D3 也可以如实记录。

残留问题只在于**投入判断**：若某点实际要求高于标注（例如高阶导数在基础班的实际要求包含"会求简单函数的高阶导数"，按 D3 更合适，而 map 标为「理解」），T 会偏低，导致"刚够 D2 就停止投入"。

- **处理方式**：这类调整应改 map 的「数一要求」并写明依据，不在教学现场临时改。改之前先记入本节。

## 三、人格模块

### P2 · 人格激活依赖范例而非规则

实测结论：**只写禁令、不给语态范例时，人格完全不会激活**（首轮冷启动测试三条回复全是中性助手腔）。补入 5 条语态基准与场景手册后，第二轮才稳定。

- 现状：`SKILL.md` 的「语态基准」与 `persona-playbook.md` 已补齐，并写明"前几轮必须读"。
- 残余风险：换到按需加载更激进的宿主时，`persona-playbook.md` 可能不被加载，人格退化会重现。
- 重要：该模块是**可摘除的表达层**。摘掉后教学判定、状态迁移、记录格式完全不受影响。**角色行为不得替代数学正确性、独立练习和效果检验。**

## 四、工程与验证

### P3 · `backup_data.py` 退出码 `2` 有两种含义

`2` 既表示"必需文件全部缺失、快照为空"（打印 `BACKUP_EMPTY`），也表示**命令行参数错误**——`argparse` 在参数非法时同样以 `2` 退出（打印 `usage:` 与 `error: unrecognized arguments:`）。最常见的触发方式：`--dest` 后面跟了含空格却没加引号的路径。

- 后果：自动化调用如果只看退出码，会把"参数写错"误判为"数据全缺失"，从而触发错误的补救动作。
- 现有缓解：README 第九节 9.6 已把这条写明，并要求"看输出内容判断，不要只看数字"。
- 本轮未修：改退出码属于接口变更，会破坏已有的调用方约定。若将来重排退出码，应把参数错误独立成 `5` 或直接透传 `argparse` 的退出码并加前缀。

### P3 · 只在 Windows 上验证

脚本用 `os.path` / `pathlib` 拼路径，跨平台可用；文档中的路径写法已统一为 `/`。但 macOS 与 Linux 未实际运行过，中文文件名在非 UTF-8 locale 下的表现未测。

### P3 · 无自动化测试

两个脚本没有单元测试。`due_review.py` 的容错设计是"任何异常都降级为一行 `DUE_REVIEW_FAILED:` 并退出 0"，这让静默退化难以被发现——降级本身不可观测。

### P3 · 未做效果验证

本项目**没有**任何对照实验、样本量或成绩数据，也不打算宣称能提高分数。已有的使用记录是个人学习日志，不是有效性证据。
