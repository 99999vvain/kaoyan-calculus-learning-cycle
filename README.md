# 考研高数学习闭环 · Kaoyan-Calculus-Learning-Cycle

**Status: Experimental**（候选版 v1.3.7；当前为**私有仓库**，尚未公开发布）

一个面向考研数学一高等数学第一轮基础复习的 AI 陪学工作流。它把"每天 30~45 分钟复习"变成一份可追溯的记录：定计划、查前置、讲概念、出题、批改、独立检验、写台账、排复习，跨会话接得上。

它最核心的一条设计不是"教得多好"，而是**不肯随便说你会了**：只有零提示、限时内、独立做对的记录，才允许把知识点标成 `已掌握`。听到"我懂了"，只会记成 `已学待验`。

## 关于这个项目，先说清楚四件事

**1. 它现在是我自己用的，个人属性极强。**

这套规则长成现在这样，是因为它服务于一个人的具体习惯：一套特定的讲义、每天半小时的碎片时间、以及"不许糊弄自己"这条底线。里面有不少硬性偏好——禁止空泛鼓励、必须报告实际用时、同一任务最多顺延一次、讲义页码只认印刷页。这些**不是普适真理**，换个人很可能不适用。README 里写"不适用"的部分，请认真看。

**2. 改起来非常简单。**

所有规则都是纯文本：`SKILL.md` 是主指令，`references/` 下每个文件管一件事（四维判据、教学规则、数据格式、督学、讲义摄入、知识地图、计划模板、人格手册）。想改判定标准就改 `assessment-rubric.md`，想改语气就动 `persona-playbook.md`，想换掉人格直接删掉那一节——**不会影响任何教学判定**。数据文件是四个普通 Markdown 表，不依赖数据库。

**3. 非常希望你来提意见，尤其是反对意见。**

最有价值的反馈不是"做得不错"，而是"这条规则在我的情况里判错了"。如果你按 README 装完卡在某一步、或者发现某条规则在真实场景里荒谬，那就是我要的东西。详见 [`CONTRIBUTING.md`](CONTRIBUTING.md)。

**4. 这个仓库里的文字和脚本，有 AI 参与生成。**

不是在括号里补一句免责声明了事，而是具体到哪部分：

| 内容 | 实际来源 |
|---|---|
| `SKILL.md`、`references/` 下的规则文本 | 维护者定方向、逐条讨论与验收，AI 起草成文 |
| `references/knowledge-map.md` | 八章骨架按公开的考纲板块归属，**99 个知识点的拆分、`K-章.节.序` 编号、前置依赖、深度等级全部由 AI 生成** |
| `scripts/due_review.py`、`scripts/backup_data.py` | AI 编写，只用标准库，无第三方代码 |
| `README.md`、`TESTING.md`、`docs/` | AI 编写 |

由此产生两个你需要知道的后果：

- **知识地图没有逐条对照过考纲原文。** 它是 AI 按通行板块归纳的骨架，不是官方大纲的转录，也**不是**从某份讲义目录搬来的（维护者没有提供过讲义目录结构）。准确度靠使用中逐点验证，目前只验到台账里那几十个点，其余未校核。发现不对，以官方大纲或你的讲义为准。
- **版权归属与最终责任在维护者本人，但作者身份不隐瞒。** "AI 参与生成"是披露问题，不是授权问题：按 MIT 与 CC BY 4.0 对外授权时，授权人仍需对内容负责。你复用本项目时，同样建议照此标注。

**正在考虑加入的方向**：费曼学习法、行为设计学等小型功能组块（尚未开始设计，见第五节）。

## 一、它解决什么问题

考研复习的常见失效点不是"没学"，而是**学了没留下痕迹**：昨天卡在哪、哪道题错过、这个知识点到底算不算会，全凭记忆。等到第二轮复习，等于从零开始重新判断。

本项目把这件事变成四个 Markdown 文件、一套固定判定规则和两个脚本：

- **进度可查**：哪些点会、哪些点只是"听过"、哪些错题到期了，一句话能答。
- **判定可核**：为什么这个点从 D2 升到 D3，证据写在台账里，能复核。
- **边界清楚**：没报时间就写 `未记录`，不估；没做独立题就不升级，不放水。

## 二、目标用户与适用范围

**适用**：准备考研数学一、正在做第一轮高等数学基础复习、愿意做题并如实报告对错的人。默认节奏是每天 30~45 分钟。

**不适用**：

- 线性代数、概率论与数理统计、高考数学 —— 不覆盖。
- 整卷模考、分数预测、择校建议 —— 不在范围内。
- 想要"AI 替我学"的 —— 本项目所有判定建立在你的真实作答上，不做替代。

## 三、当前状态（请按这个判断是否值得试）

**早期实验版本。真实使用时长：2 天 / 4 次会话。**

| 项 | 实际数字 |
|---|---|
| 真实学习会话 | 2 天，4 次 |
| 累计作答 | 约 13 题 |
| 错题记录 | 5 条，全部完成复测 |
| 应试能力记录 | 8 行，其中 5 行用时为 `未记录` |
| 讲义摄入 | 2 讲 |

这意味着：**主流程跑通了，长周期规则还没验证过。** `需回炉`、章末复习、周复盘在真实使用中一次都没触发。请不要把本项目描述为"经过验证有效"——它没有对照实验、没有样本量、没有任何成绩数据。

## 四、已实现的功能

- **五种模式路由**：开始学习 / 陪伴学习 / 专项学习 / 结束学习 / 进度检查。
- **四个数据文件与写入白名单**：只追加不覆盖，明确哪些列可改、哪些值合法。
- **四维独立记录**：G 学习梯度（怎么教）/ D 知识深度（理解到第几层）/ B 知识广度（连得多远）/ 应试能力（限时能否做对），**不合并、不算百分比**。
- **七状态机**：未开始 / 在学 / 已学待验 / 待复习 / 复习中 / 已掌握 / 需回炉。
- **目标深度 T 与记录深度 D 分离**：T 决定"还练不练"，D 只认证据，不封顶。
- **提示分级 L0~L3**，只有 L0 能作为掌握证据。
- **错因五分类** → 固定补救动作（概念性 / 方法性 / 计算性 / 审题性 / 时间性）。
- **难度调整 R1~R12**，含"同一任务最多顺延 1 次，第 2 次必须砍量或拆小"。
- **讲义摄入协议**：页码只认印刷页，读不出就标 `未确认`，不按偏移量推算。
- **三档计划模板**：15 / 35 / 45 分钟。
- **两个脚本**：`due_review.py`（只读，输出到期复习清单）、`backup_data.py`（备份四个数据文件，可异地）。
- **可选人格层**：「大肥鱼老师」，只改表达不改判定，可用一句「别演了」关闭。

## 五、尚未实现的功能（Roadmap · Planned / Not implemented）

**以下均未实现，不要当作已有功能。** 不承诺完成时间。

目前有两个方向正在考虑，想做成**小而独立的组块**——能单独开关，不侵入现有判定：

- **费曼学习法组块**：让学习者用自己的话把知识点讲一遍，据此区分"会做"与"真懂"。现在的 D2 判据里只有"复述推导主线 ≥2 步"这一条评价标准，够不上一个机制。难点在于：怎么判断一段复述是"背出来的"还是"讲明白了"。
- **行为设计学组块**：连续学习天数、启动摩擦、正向反馈、节奏提示。现在的规则只有负向约束（禁空泛鼓励、禁情感操纵），**没有任何正向激励设计**——这是明显的缺口。难点在于：正向机制和"不许糊弄自己"的判定纪律天然有张力，做不好就变成打卡式自我安慰。

两个组块都还在"考虑要不要做、怎么做"的阶段，**没有设计文档，也没有排期**。如果你对这两块有想法或反例，欢迎直接提。

## 六、安装、初始化与基本使用

### 6.1 装之前，先确认三件事

| 项 | 怎么确认 | 说明 |
|---|---|---|
| Python 3.8 以上 | 命令行执行 `python --version`（macOS / Linux 多为 `python3 --version`） | 两个脚本只用标准库，**不需要 `pip install` 任何东西**。实测环境是 3.13，3.8~3.12 未实测 |
| 宿主能读写本地文件 | 看你的平台是否允许 AI 直接读写磁盘文件 | 全部功能建立在"能读四个 Markdown、能追加表格行"上。只能对话、碰不到文件的平台，装上也用不了 |
| 能解压、能访问文件夹 | — | 需要手工把目录放进技能目录，这一步没有安装包 |

另外两条：

- **不需要**网络、账号、API Key。规则全在本地。
- 拿到的是压缩包时**先解压**，别把 `.zip` 直接放进技能目录——宿主读不到里面的 `SKILL.md`。

### 6.2 安装

#### 第 1 步：找到要复制的那一层

要复制的不是"外面的大文件夹"，而是**直接包含 `SKILL.md` 的那一层**。判断办法：

```bash
ls SKILL.md          # Windows 命令提示符：dir SKILL.md
```

能列出来，你就在这一层。再看一眼它的名字：

```bash
head -4 SKILL.md     # Windows：more SKILL.md
```

应看到 `name: kaoyan-calculus-learning-cycle`。**建议把这一层的文件夹名改成与 `name` 完全一致**，日后好认（本机同目录下其他技能都是这么放的；这不是强制要求）。

#### 第 2 步：复制进宿主技能目录

| 平台 | 用户级技能目录 | 验证状态 |
|---|---|---|
| Windows | `C:\Users\<你的用户名>\.workbuddy\skills\` | 维护者本机实测该路径存在、技能可被识别 |
| macOS / Linux | `~/.workbuddy/skills/` | **未实测** |

关于 `~`：它是"当前用户主目录"的简写，不是字面量。Windows 上 `~` 相当于 `C:\Users\<你的用户名>`，macOS 是 `/Users/<你的用户名>`，Linux 多为 `/home/<你的用户名>`。所以 `~/.workbuddy/skills/` 在 Windows 上就是上表第一行那个路径——**但别把 `~` 直接粘进资源管理器地址栏**，它不会被识别。

不会用命令就直接在资源管理器 / 访达里拖，效果一样。

#### 第 3 步：检查复制结果

正确结构是**只有一层** `kaoyan-calculus-learning-cycle`：

```text
<技能目录>\kaoyan-calculus-learning-cycle\
  SKILL.md
  README.md
  references\
  assets\
  scripts\
  docs\
```

最常见的错误是**多套了一层**：

```text
<技能目录>\kaoyan-calculus-learning-cycle\kaoyan-calculus-learning-cycle\SKILL.md   ← 错
```

出现这种，把里面那层提上来，或删掉外面那层。

#### 第 4 步：让它生效 —— 这一段需实机确认

> **需结合当前 WorkBuddy 版本实机确认。**
> 本文写作时查阅了 WorkBuddy 官方文档（`workbuddy.cn/docs/workbuddy/Overview`、`/Create-Task`），**其中没有关于技能安装位置、刷新方式或菜单入口的任何说明**。所以这里不写"点哪个按钮"——写了就是编的。
>
> **已知**：维护者本机（Windows 11）把技能目录放进 `%USERPROFILE%\.workbuddy\skills\` 后，技能可被识别。这是实机观察，不是文档引用。
> **未知**：新装技能后怎么刷新列表——要不要重启客户端、有没有刷新按钮、新开任务是否即生效，取决于你的版本。

没反应时按顺序试：① 新开一个任务会话再试；② 重启客户端；③ 到你当前版本的设置 / 技能管理页面里刷新。三条都不通，就是该记录下来去提 issue 的情况（见第十节）。

#### 第 5 步：确认装好了（不依赖任何界面）

在会话里让它做一件必须读到技能才能做的事，例如：

- 「列出你当前可用的技能名字」
- 或「读一下 `kaoyan-calculus-learning-cycle` 的 `SKILL.md`，告诉我它有几种模式」

答出具体内容（比如"五种模式"）说明指令已被读到。答"没有这个技能"或答得很空泛，回第 3 步查目录层级。

### 6.3 首次初始化

**初始化之前：目录里应该有什么、不该有什么**

应该有 26 个文件：`SKILL.md`、`references/` 8 个、`assets/templates/` 4 个、`scripts/` 2 个，其余为说明文档（完整清单见第十二节）。

**不应该有** `data/`。有这个目录说明你复制的是别人已经在用的副本——**先把它挪到别处**，否则会带着别人的记录往下走。

**首次触发时的预期行为（这是本项目的规定，不是已验证事实）**

1. 明确说明"没找到历史记录，按第一次来"，**不编造进度**；
2. 创建 `data/`；
3. 从 `assets/templates/` 复制四个空白文件做底稿（**不要让它现编表头**，脚本依赖固定表头）；
4. 视情况做一次 15 分钟基线诊断（极限计算 / 求导 / 基本积分各 1 题，可拆 2~3 次）；
5. 依诊断结果写台账首版。

**初始化后应该出现的四个文件**

| 文件 | 关键结构（坏了脚本就读不出来） |
|---|---|
| `data/学习进度.md` | 必须有 `## 状态快照` 段，含 10 个键：考试类别 / 备考阶段 / 当前章节 / 当前知识点 / 当前讲次 / 当前梯度 / 最近学习日期 / 待复测 / 未完成任务 / 数据版本；另需一张含 `ID` 与 `next_review` 两列的台账表 |
| `data/错题档案.md` | 需一张含 `ID` … `next_review` … `状态` 列的错题表 |
| `data/每日学习记录.md` | 可以只有文件头和注释模板，学习后才追加 `## 日期` 块 |
| `data/讲义索引.md` | 7 列表头：收到日期 / 讲次/标题 / 页码范围 / 覆盖知识点ID / 本讲例题数 / 讲义强调点 / 备注 |

**怎么检查（本节命令均在本机实测过）**

```bash
python scripts/due_review.py
```

看`SNAPSHOT` 那一行。它只有三种结果（其余行是 Today / 到期项 / 最近学习块，都在 `SNAPSHOT` 前后打印）：

| 输出 | 含义 | 怎么办 |
|---|---|---|
| `SNAPSHOT=OK 当前=… 梯度=… 最近=…` | 10 个键齐全，表头没坏 | 可以开始用 |
| `SNAPSHOT_INCOMPLETE: 缺 …` | 缺哪几个键就补哪几个。脚本只检查键，不检查内容 | 补键，或重新从模板复制 |
| `DUE_REVIEW_FAILED: 缺少文件 …` | `data/` 里少了文件，或路径不对 | 回上表核对文件名，注意大小写与全角 |

**必须分清的两件事**

- **已验证**：脚本对这四个文件的行为。上面三种输出都是本机用空白模板真跑出来的。
- **未验证**：模型会不会真的建 `data/`、会不会照抄模板、会不会先说"没找到历史记录"。这些是模型行为，**仅凭 README 无法保证**。若它跳过初始化直接开讲，就是缺陷，请按第十节记录。

### 6.4 基本用法

| 你说 | 预期行为 |
|---|---|
| 「开始今天的高数」 | 读记录 → 复述上次状态 → 列到期复习 → 给 5 行简报计划 → **等你确认** |
| 「我在看极限」 | 只记下当前任务，不强行开讲 |
| 「讲讲高阶导数」 | 进专项模式：定义原话 → 推导主线 → 适用条件 → 例题 → 独立练习 |
| 「今天学完了」 | 核对计划与实际 → 写四个文件 → 更新状态 → 排复习 → 给下次建议 |
| 「最近进度怎样」 | 基于真实记录给 ≤8 行分析，数据不足时明说"无法判断" |

### 6.5 怎么确认它真的写进去了

**不要拿"它说已写入"当证据。** 文件是唯一证据。

学完一次后，按下面三步核对：

**1. 先跑一次，记下两个数**

```bash
python scripts/due_review.py
```

记两个值：`LAST_DAY=<日期>` 这一行，以及 `统计 到期=… 待验或待复习=… 回炉=…` 这一行。

**2. 直接打开文件看末尾**

```bash
tail -30 data/每日学习记录.md      # Windows：more data\每日学习记录.md
```

应看到新追加的 `## 日期 · 时长 · 章节` 块，块内有 14 个固定 bullet。**没有新块就是没写进去**，不论它怎么说。

**3. 再跑一次，看数字变了没**

`LAST_DAY` 变成今天的日期、`统计` 数字有变化，说明这一轮确实落库了。

**如果没变化，按这个顺序记证据**（就是第十节模板要的东西）：

- 完整命令 / 你发出去的原始指令；
- 它的原话（它说写了哪个文件）；
- 四个文件的实际修改时间（Windows `dir data\`，macOS/Linux `ls -l data/`）；
- `due_review.py` 的前后两次输出。

## 七、平台依赖与兼容性

`SKILL.md` 是普通 Markdown 指令，frontmatter 只有 `name` / `description` / `version` 三个通用字段。移植到其他 Agent 平台时需要自行确认：

| 项 | 说明 |
|---|---|
| 触发方式 | 本项目靠在 `description` 里列「触发词」声明何时启用；你的平台若用别的机制（如 slash command），需相应改写 |
| 按需加载 | 本项目假设宿主能按需加载 `references/` 下的单个文件。不支持时会把全部内容塞进上下文，注意预算 |
| 文件写入 | 指令里写的是**能力**（读文件、追加表格行），不是具体工具名。按你平台的工具替换 |
| 图片输入 | 讲义摄入链路依赖读图。不支持读图时，该链路应降级为"只接受 PDF 或粘贴文字" |
| 路径 | 仓库内部的互相引用一律用相对路径（如 `references/assessment-rubric.md`），不含绝对路径。但**安装路径必须由你自己定位**：第六节的 `~/.workbuddy/skills/` 只是其中一种，且只实测过 Windows。其他平台或安装渠道可能不同 |

## 八、学习记录怎么建、怎么维护

四个文件，各管一件事：

| 文件 | 职责 | 写入方式 |
|---|---|---|
| `data/学习进度.md` | 状态快照 + 知识点台账 + 应试能力记录 | 快照整段重写；台账只加行或改 4 列；应试表只加行 |
| `data/错题档案.md` | 错题与复习排期 | 只加行；复测记录单元格追加 |
| `data/每日学习记录.md` | 按日学习块（14 个固定 bullet） | 只追加 `## 日期` 块 |
| `data/讲义索引.md` | 讲次 ↔ 知识点对照 | 只加行 |

维护纪律（完整版见 `references/data-format-spec.md`）：

- **只追加，不覆盖**。禁止重排、合并、删除历史行。
- **合法值有限**：状态只有七个，G/D/B 只能取枚举单值，禁止 `%`、`D2.5`、`G2+`。
- **时间必须标来源**：`手动` / `自动` / `未记录`。没报告的时间写 `未记录`，不估、不用计划时长顶替。
- **写入失败必须当场说明**：说清哪个文件、失败原因、哪些内容没写进去，不得只说"已记录"。

## 九、备份、恢复与更新

> **这是本项目最脆弱的一环，请务必读完。** `data/` 在技能目录**内部**，覆盖式升级或整体替换技能目录时，记录会跟着一起没。

### 9.1 备份存在哪：两个位置，别混

`backup_data.py` 有两种落点，**默认那个不算异地**：

| 命令 | 备份实际写到 | 算不算异地 |
|---|---|---|
| `python scripts/backup_data.py` | `data/backup/<日期>/`（技能目录内部） | **不算**。整目录被覆盖时一起消失 |
| `python scripts/backup_data.py --dest <路径>` | `<路径>/<日期>/` | 算。前提是 `<路径>` 不在技能目录里 |

注意 `--dest` **不是"只备份到异地"**：本地快照照写，异地是额外一份。带 `--dest` 时输出里会有两个段落。

### 9.2 执行备份（命令均在本机实测过）

命令都在**仓库根目录**（能看见 `SKILL.md` 的那一层）执行。

**Windows（命令提示符 / PowerShell）**

```bat
python scripts\backup_data.py --dest "D:\高数备份"
```

**路径含空格必须整体加引号**，例如 `--dest "D:\我的 备份\高数"`。不加引号时命令行会把路径拆成两段，脚本直接拒绝执行，报：

```text
backup_data.py: error: unrecognized arguments: 备份
```

退出码是 `2`——**这是参数错误，不是"数据全缺失"**，两者退出码相同，靠输出内容区分（见 9.6）。

**macOS / Linux**

```bash
python3 scripts/backup_data.py --dest ~/高数备份
```

`--dest` 支持 `~`，脚本会自己展开成主目录。**这两个平台的示例未实测。**

**实际输出长这样**（本机用空白模板跑的真实结果；你的路径、日期、字符数会不同）：

```text
[本地快照] ...\data\backup\2026-10-22
  学习进度.md             639 字符
  错题档案.md             384 字符
  每日学习记录.md           336 字符
  讲义索引.md             154 字符
[异地快照] ...\备份 目标\2026-10-22
  学习进度.md             639 字符
  错题档案.md             384 字符
  每日学习记录.md           336 字符
  讲义索引.md             154 字符

完成：本地 1513 字符，异地 1513 字符
```

字符数不会是 0（四个模板本身就有内容）。看到 `0 字符` 说明文件是空的或没读到。

### 9.3 怎么确认备份成功了

三条都要过，缺一条都不算：

1. **退出码为 `0`**：Windows 执行 `echo %errorlevel%`，macOS/Linux 执行 `echo $?`；
2. **末行是** `完成：本地 N 字符，异地 N 字符`，且四个文件字符数都非 0；
3. **目录里真的躺着四个文件**——自己去看：

```bash
ls "<路径>/<日期>/"        # Windows：dir "D:\高数备份\2026-10-22"
```

要更硬的核对就比哈希（四个文件都是纯文本）：

```bat
:: Windows
certutil -hashfile "D:\高数备份\2026-10-22\学习进度.md" MD5
certutil -hashfile "data\学习进度.md" MD5
```

```bash
# macOS / Linux
md5sum "~/高数备份/2026-10-22/学习进度.md" data/学习进度.md
```

两行哈希一样，就是同一份。

### 9.4 更新

**更新前**

1. 执行 9.2 的备份；
2. 按 9.3 确认成功。**没确认成功就不要往下做**；
3. 把旧版技能目录整个另存一份（含 `data/`），放在技能目录之外。

**更新后**

1. 看 `data/` 四个文件还在不在、行数是否合理（跑一次 `due_review.py` 一并看）；
2. 数据没了就按 9.5 恢复。

### 9.5 恢复

**先确认当初备份到哪**，恢复源就是那里：

| 当初执行的命令 | 恢复源 |
|---|---|
| 只有默认备份 | `data/backup/<日期>/` |
| 带过 `--dest` | `<路径>/<日期>/` —— **优先用这个**，因为它在技能目录外，更可能是仅存的一份 |

**恢复步骤**

1. **先备份当前的 `data/`。** 恢复是覆盖操作，万一恢复源反而是旧的，你会把新数据一起盖掉。这步不能省。
2. 把恢复源里四个文件复制到 `data/`，覆盖同名文件：

```bat
:: Windows
copy /Y "D:\高数备份\2026-10-22\*.md" "data\"
```

```bash
# macOS / Linux
cp -- "~/高数备份/2026-10-22/"*.md data/
```

3. **确认四个文件都在、都不是 0 字节**：

```bash
ls -l data/*.md      # Windows：dir data\*.md
```

4. 跑 `python scripts/due_review.py`，看到 `SNAPSHOT=OK` 且 `统计` 那行与你记忆中的进度大致相符，才算恢复完成。出现 `SNAPSHOT_INCOMPLETE` 说明恢复来的是坏文件或半截文件，换一个日期目录重来。

四个文件都是纯 Markdown，**脚本不能用时用任意编辑器手工复制也可以**，但恢复完同样要走第 4 步核对。

### 9.6 备份脚本出错时

`backup_data.py` 用退出码区分结果，并打印可检索的标记：

| 退出码 | 含义 | 标记 | 该做什么 |
|---|---|---|---|
| `0` | 完整备份成功（带 `--dest` 时本地与异地都成功） | `完成：…` | 按 9.3 再确认一眼目录 |
| `1` | 找不到 `data/` | `BACKUP_FAILED` | 还没初始化，或不在仓库根目录执行 |
| `2` | 必需文件全部缺失，快照为空 | `BACKUP_EMPTY` | `data/` 里没有那四个文件，先按 6.3 初始化 |
| `3` | 必需文件部分缺失，快照不完整 | `BACKUP_INCOMPLETE` | **快照只写了一半，恢复会缺文件**。补回缺失文件后重跑 |
| `4` | 目标目录不可用（建不了或不可写） | `BACKUP_FAILED` | 检查 `--dest` 路径：是不是指到了一个已存在的**文件**上？路径含空格有没有加引号？ |

> **退出码 `2` 有两处来源，别混**：一是上表的"必需文件全缺失"（会打印 `BACKUP_EMPTY`）；二是**命令行参数写错**，比如 `--dest` 后面跟了带空格的未加引号路径——这时打印的是 `usage: backup_data.py …` 和 `error: unrecognized arguments: …`，脚本压根没开始备份。**看输出内容判断，不要只看数字。**

看到非 `0` 就**不要继续更新**：先手工把 `data/` 整个文件夹复制出去。

**一个实测细节**：退出码 `4` 时本地快照其实已经写成功了（脚本先写本地再写异地），输出里会明说"本地已写入 N 字符，异地未完成"——**异地那份没有**，别把本地那份当成异地备份。
